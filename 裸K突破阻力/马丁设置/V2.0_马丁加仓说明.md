# 裸K突破阻力 V2.0：固定手数 → 马丁加仓（接入 RiskMartinModule V4.3 马丁阶梯）

V2.0 基于 V1.8，只研究 XAUUSD，不包含 V1.9 的多品种尺度。

## 一、模块怎么接的

`RiskMartinModule.mqh` V4.3 是 **MQL5 模块**，用到了 `CTrade`、`PositionGet*`、`HistoryDeal*`、`input group`、`PERIOD_M10` 等。MT4 编译器不能直接 `#include` 它。

所以我把它的**马丁引擎**逐式移植成 MQL4 版本，存为 `马丁阶梯模块_MT4_V4.3移植.mqh`。这个文件只计算手数，不读写任何订单。

| 原模块（马丁部分） | MQL4 移植 |
|---|---|
| `InitMartin(30 格, 层数, lotScale)`：层数钳位 1~30，倍率在装载时一次性乘入 | 相同 |
| `GetMartinLots(currentOrders, multiplier)`：表内取第 n 格；表外 = 表尾 × 倍数^超出层数，最多复利 12 步 | 相同 |
| `NormLots`：先钳位到最小/最大手数，再按步长向下取整；最小手数不是步长整数倍时向上补齐 | 相同 |
| 品种手数规格读取 `SymbolInfoDouble` | 改用 `MarketInfo` |

**没有接入的部分：** 服务器端 SL/TP 同步、对冲强平、浮亏浮盈钉死、回收熔断、单向翻转、K线配额。

- 它们依赖 MQL5 的持仓与成交 API。
- 它们和本 EA 自带的整篮止盈、[P2] 移动锁利、[P9] 超时降级、浮亏止损功能重叠。两套离场逻辑同时运行会互相冲突。

## 二、新增参数

| 参数 | 中文名 | 说明 |
|---|---|---|
| `InpMartinMode` | [M1]马丁加仓模式 | 关闭 = 固定手数，与 V1.8 逐笔一致。<br>仅阻力加仓：首单和突破加仓用第 1 格，第 n 次阻力加仓用第 n+1 格。<br>链内逐单：链内第 N 单用第 N 格，突破加仓也随层放大。 |
| `InpMartinLotScale` | [M1]马丁全局手数倍率 | 阶梯每格乘以此值。基准手数 = 第 1 格 × 倍率。开启马丁后，「每单手数」不再使用。 |
| `InpMartinLayers` | [M1]马丁阶梯层数 | 1~30。超过层数后，手数 = 表尾 × 表外倍数^超出层数。 |
| `InpMartinMultiplier` | [M1]表外复利倍数 | 1 表示表外一律用表尾手数。最多复利 12 步。 |
| `InpMartinMaxBasketLots` | [M2]篮子总手数上限 | 适用所有模式，0 = 不限。如果开这一单后总手数会超过上限，就不开。首单被拦会记入开单诊断。 |
| `InpMLot1`~`InpMLot30` | [M1]马丁第 1~30 格手数 | 30 格阶梯。 |

**其余说明：**

- **金额参数按基准手数缩放。** 止盈、锁利、止损、降级目标都按基准手数计算（[P6] 金额缩放），不随层数放大。手数变大后，篮子会更快达到同样的止盈金额，这正是马丁的用意。
- **阻力单计数不怕重启。** 每条链里已有几张阻力单，是从订单注释前缀"阻力"统计的，断线或重启后会自动恢复。如果改了「阻力加仓注释前缀」，计数会从 0 重新开始，下一单手数只会偏小，不会偏大。
- **资金体检会估算满仓手数。** 设了上限就按上限算；没设上限就按最坏情况算，即单链从第 1 格一直加到最大持仓单数。

## 三、风险结论（务必读）

结论来自技能库"扫描篮子风控"的蒙特卡洛配对实验：同一条行情路径，唯一变量是手数。

- 马丁的收益约为固定手数的 **2.3 倍**，最差回撤约 **7.7 倍**，篮子手数峰值约 **22.6 倍**。
- 真正的爆仓通道是**手数峰值**，也就是保证金被占满，而不是止损。所以马丁模式下，[M2] 篮子总手数上限是必需项。
- 胜率接近 100% 是一种假象。止损金额远大于单篮止盈，止损几乎不会触发，直到真正触发的那一次。

**机制示意：** 用设置1 报告里 08-26 那篮的真实成交价重新计算。这不是回测，后续路径会随之改变。

| | 固定 0.5 手 | 马丁（仅阻力加仓，×50） |
|---|---|---|
| 各单手数 | 0.5 × 6 | 0.5 / 0.5 / 0.5 / 1.0 / 1.5 / 2.0 |
| 04:47 浮亏 | −2,055 | −2,687（深 1.3 倍） |
| 达到止盈 650 所需反弹价位 | Bid ≥ 4648.13 | Bid ≥ 4644.67（少反弹约 3.5 美元） |

马丁就是这种交换：浮亏更深，但只要价格回一点就能平掉。如果价格一直不回头，越加越大的手数会把亏损放大到浮亏止损为止。浮亏止损 = 2500 × 50 = 12.5 万，比 5 万本金还大。

## 四、回测设置（回测由你完成）

`马丁设置/` 目录下的三份 set，都以 `A_设置1加P9_超时120分保本.set` 为基础。共同点：

- 首单 0.5 手（第 1 格 0.01 × 倍率 50），篮子总手数上限 40 手。设置1 固定手数时篮子峰值是 38 手，两边的手数天花板基本相同。
- 其余参数与设置1+P9 完全相同。

| 文件 | 模式 | 阶梯（× 50 后的实际手数） |
|---|---|---|
| `A_马丁仅阻力加仓_首单0.5手_上限40手.set` | 仅阻力加仓，10 层，表外倍数 1 | 0.5 / 0.5 / 1 / 1.5 / 2 / 3 / 4.5 / 6.5 / 9.5 / 14 |
| `B_马丁链内逐单_首单0.5手_上限40手.set` | 链内逐单，30 层 | 每 3 单加 0.5 手：0.5 ×3、1.0 ×3、…，第 30 格 5.0 |
| `优化_马丁仅阻力加仓_篮子手数上限10至60_6次.set` | 同 A | 只扫篮子总手数上限：10 / 20 / 30 / 40 / 50 / 60 |

**对照组就是现有的 `深挖设置1/A_设置1加P9_超时120分保本.set`（固定手数）。** 它在 V2.0 上运行时马丁关闭，与 V1.8 逐笔一致。

**建议的验证步骤：**

1. 先在原来那段历史（2026.08.16–08.28，5 万本金）上，用对照组、马丁 A、马丁 B 各跑一次。
2. 用 `工具/MT4报告解剖器.py 对照.htm 马丁A.htm` 对比两份报告，重点看：
   - 第一处分叉在哪一笔。
   - 最深的篮子分别是哪个，峰值手数多少。
   - 报告头的最大亏损。
3. 换到至少 3 个月的历史上再跑一次。马丁的代价只会出现在"一直不回头"的行情里，10 天的样本很可能一次都碰不上。
4. 评判标准不看净利，看"净利 ÷ 最大回撤"和"篮子手数峰值"。如果马丁版的这个比值不比固定手数高，就没有理由上马丁。

## 五、部署

1. 把 `裸K突破阻力_复刻_V2.0.mq4` 和 `马丁阶梯模块_MT4_V4.3移植.mqh` 放进 `MQL4\Experts`。原来的三个 .mqh 也要在同一目录。
2. 在 MetaEditor 编译，确认 0 错误。这个环境里没有 MT4 编译器，所以只做过静态审计：括号配平、标识符声明、格式符与参数个数匹配、与 V1.8 的交易路径逐行对比。
